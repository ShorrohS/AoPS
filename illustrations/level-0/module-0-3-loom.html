Type A — Chapter Hero FIG 0.3-A The Jacquard Loom — Instructions Stored in Holes
The Jacquard loom (1804) — the first machine to execute stored instructions. Left: the loom frame with vertical warp threads interlaced with horizontal weft threads producing a woven pattern. The Jacquard head at the top reads the active punch card. Right: the card encoding — a hole allows a needle to pass through, raising the corresponding heddle and lifting that warp thread; a blank blocks the needle, leaving the thread down. Each row of holes encodes one weft pick. The sequence of cards is a program.
Type C — Concept Diagram FIG 0.3-B Punch Card Encoding — Pattern to Holes to Binary
The encoding pipeline. Stage 1: a 5-row weave pattern where dark cells indicate the weft thread passing over the warp. Stage 2: the corresponding punch card — a hole appears wherever the weft must cross over (dark cell = 1 = hole). Stage 3: each row reads as a binary byte. Row 1 (1 0 1 0 1 0 1 0) produces a plain alternating twill; Row 3 (1 1 0 0 1 1 0 0) produces a wider herringbone. The sequence of cards is the complete fabric program.
Type C — Concept Diagram FIG 0.3-C Stored Instructions — From Card Chain to Stored Program
The intellectual lineage of stored instructions. Jacquard (1804): instructions as a physical card chain — sequential, unmodifiable. Hollerith (1890): cards encode data records, separating program logic from data content. Von Neumann (1945): instructions and data share the same memory — the program can now inspect and modify itself. Modern CPUs (2024): the identical architecture, shrunk to nanometre scale. The Jacquard loom's core insight — that instructions can be stored externally and executed in order — flows unbroken through 220 years of computing.
Type B — Historical Reconstruction FIG 0.3-D Jacquard's Workshop — Lyon, 1804
Historical reconstruction of a Jacquard loom workshop, Lyon 1804. An operator feeds the active punch card to the Jacquard head, which reads each hole and controls the heddle harness below. A card library on the right holds multiple pattern programs — different cards produce different fabrics on the same loom. This is the first practical separation of hardware (loom) from software (card programs), a concept Babbage explicitly borrowed when designing the Analytical Engine.
Type F — Simulation Figure FIG 0.3-E Card Pattern Simulator — 8×8 Weave Grid with Binary Output
Static view of the Module 0.3 simulation. Left: the 8×8 pattern editor with a diamond motif drawn — dark cells indicate where the weft thread passes over the warp. Centre: the automatically generated punch card with holes punched at the corresponding positions. Right: the binary encoding — each row produces one byte of pattern data, with 1s (red) corresponding to holes and thread lifts. The complete 8-row card is the program that produces the diamond weave.
