Type A — Chapter Hero FIG 3.2-A Fetch–Decode–Execute — The Three-Step Cycle That Runs Every Program
The Fetch-Decode-Execute cycle — the fundamental operation of every processor ever built. The Program Counter (PC, red) holds the address of the next instruction. Fetch: the CPU reads the byte(s) at address PC into the Instruction Register (IR, gold) and increments PC. Decode: the control unit examines the IR opcode bits to determine what operation to perform and which registers are involved. Execute: the ALU performs the computation (here ADD R1, R2 adds R1's value to R2's value) and writes the result to the destination register. The cycle repeats immediately — billions of times per second in a modern CPU.
Type D — Process Diagram FIG 3.2-B PC and IR State Trace — Five Instructions Step by Step
A five-instruction state trace. Cycles 1–4 execute sequentially: PC increments by 1 after each fetch. Cycle 5 (JMP 0x0000) overwrites PC with 0x0000 instead of incrementing it — this is how conditional branches, function calls, and loops are implemented at the machine level. Every high-level control flow construct (if, while, for, return) compiles down to a variation of the JMP instruction altering the PC.
Type D — Simulation Figure FIG 3.2-C FDE Trace — Executing ADD R1, R2 Step by Step
Full trace of the Fetch-Decode-Execute cycle for a single ADD R1, R2 instruction. Fetch: the Program Counter (0x100) addresses memory, loads the encoded instruction into the Instruction Register, and advances to 0x101. Decode: the control unit splits the IR into opcode (ADD), destination register (R1), and source register (R2). Execute: both register values feed the ALU, which adds them and writes the result (0x08) back to R1. Every program ever executed on a stored-program computer is simply this three-step loop, repeated billions of times per second.
