Type A — Chapter Hero FIG 3.5-A The System Bus — Address, Data, and Control Lines
The system bus connects CPU, RAM, I/O controllers, and ROM through three parallel wire groups. The address bus (red, top) carries the target memory address from the CPU to all components — only the component whose address range matches responds. The data bus (indigo, middle) carries the actual data value in either direction. The control bus (gold, bottom) carries read/write signals, clock, interrupt lines, and bus arbitration signals. A single memory read requires four steps: put address on address bus, assert READ on control bus, the target component puts data on the data bus, CPU reads the data.
Type E — Comparison FIG 3.5-B Von Neumann vs Harvard Architecture
Von Neumann (left): instructions and data share a single memory and a single bus. Simple and flexible — the program can modify itself or use memory for either instructions or data. The bottleneck: fetching the next instruction and loading a data operand require two sequential bus cycles. Harvard (right): separate instruction and data memories with separate buses. The CPU can fetch the next instruction and access a data operand simultaneously — removing the Von Neumann bottleneck. Used in microcontrollers (AVR, PIC), DSPs, and GPU shader processors where deterministic throughput matters. Modern x86 CPUs simulate Harvard internally with separate L1 instruction and data caches in front of a unified Von Neumann memory system.
Type E — Comparison FIG 3.5-C Von Neumann vs Harvard Architecture — One Bus vs Two
Von Neumann architecture (left) places all code and data in a single unified memory, accessed over one shared bus — creating the Von Neumann bottleneck where instruction fetching and data access compete. Harvard architecture (right) uses physically separate buses for instructions and data, allowing the CPU to fetch the next instruction while simultaneously reading or writing data. Modern CPUs use a hybrid: a unified DRAM but separate on-chip instruction and data caches — giving Harvard-like performance with Von Neumann-like programming simplicity.
