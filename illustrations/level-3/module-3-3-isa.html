Type A — Chapter Hero FIG 3.3-A Instruction Encoding — How an Instruction Becomes Bits
MIPS-style 32-bit instruction encoding for ADD R1, R2, R3. The instruction word is divided into fields: opcode (6 bits, identifies instruction type), RS and RT (source registers, 5 bits each — can address 32 registers), RD (destination register), SHAMT (shift amount for shift instructions, zero here), and FUNCT (refinement of opcode for R-type instructions). The entire instruction fits in one 32-bit word = 0x00422020 = four bytes in memory. The three instruction formats (R, I, J) cover all MIPS instructions — the simplicity is intentional and is the defining characteristic of RISC design.
Type E — Comparison FIG 3.3-B RISC vs CISC — Two Design Philosophies
RISC vs CISC design philosophies. CISC (x86-64, left): a single MOVSX instruction computes an address with a scaled index and offset, reads a 16-bit value, and sign-extends it — four logical operations in one binary instruction. RISC (ARM, right): the same operation requires three instructions, but each is exactly 4 bytes and does exactly one thing. RISC designs are easier to decode in parallel and pipeline. Modern x86 CPUs resolve the debate pragmatically — the frontend decodes complex x86 instructions into simple micro-operations (μops) before issuing to an internal RISC-like execution engine.
Type E — Comparison FIG 3.3-C RISC vs CISC — Two Philosophies for Designing an ISA
The RISC-CISC design spectrum. RISC (ARM, RISC-V) uses uniform-width, single-cycle instructions — simple to pipeline and decode but requires more instructions per task. CISC (x86) provides powerful multi-cycle instructions — compact programs but complex decoders. The apparent conflict resolved itself in practice: modern x86 processors internally translate variable-length CISC instructions into fixed-length micro-operations and execute them on a RISC-style pipeline. The ISA is CISC; the microarchitecture is RISC.
