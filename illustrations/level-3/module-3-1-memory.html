Type A — Chapter Hero FIG 3.1-A Memory Hierarchy — Speed vs Capacity vs Cost
The memory hierarchy pyramid. Each level trades speed for capacity. CPU registers (apex): sub-nanosecond access, ~1KB total, implemented as flip-flops on the CPU die. L1/L2/L3 caches: SRAM, 1–20ns, 32KB–16MB — automatically managed by hardware. Main RAM: DRAM, ~60ns, 8–64GB — software-addressable. SSD/NVMe: ~100μs, terabytes — persistent. HDD: ~10ms, unlimited — archival. The processor tries to keep frequently used data in higher levels; a cache miss cascades down the hierarchy, stalling the CPU until data arrives from the slower level.
Type E — Comparison FIG 3.1-B SRAM vs DRAM — Two Technologies, Two Trade-offs
SRAM vs DRAM at the cell level. SRAM (left): six transistors form two cross-coupled inverters that latch a bit stably — no refresh needed, sub-nanosecond access, but 6× the silicon area. Used exclusively for CPU caches. DRAM (right): one transistor gates a capacitor that stores charge representing the bit — but capacitors leak, so every cell must be read and rewritten (refreshed) every 64ms. Far denser and cheaper than SRAM — a single DRAM chip holds billions of cells. The 50–100ns access time is why cache misses are so expensive: the CPU must wait 50–100 cycles for data from RAM.
Type F — Simulation Figure FIG 3.1-C Memory Address Space — 8-byte Array in RAM
Memory as an addressable array. Each cell holds exactly one byte (8 bits). Addresses are sequential integers starting at 0. The string "HELLO" is stored as five ASCII bytes (72, 69, 76, 76, 79) followed by a null terminator (0) at addresses 0x0000–0x0005. Reading any byte requires specifying its address — the memory controller puts the address on the address bus and the value appears on the data bus. A 16-bit address bus can access 65,536 unique bytes. Modern 64-bit CPUs theoretically address 16 exabytes, though only 48 bits are typically implemented (256TB).
