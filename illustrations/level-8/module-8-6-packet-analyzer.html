Type A — Chapter Hero FIG 8.6-A Packet Capture Architecture — NIC to Wireshark / tcpdump
Packet capture architecture. Normally a NIC only delivers frames addressed to its MAC address. In promiscuous mode it delivers all frames it receives — enabling capture of traffic to/from other hosts on the same segment. The Berkeley Packet Filter (BPF) runs a small filter program in kernel space, dropping packets that don't match the filter expression before they are copied to userspace — this dramatically reduces overhead for filtered captures. libpcap provides a portable C API for these capabilities, used by Wireshark, tcpdump, and network monitoring tools. Modern eBPF (extended BPF) is a superset that powers Linux network observability, load balancing (Cilium), and security tools (Falco).
Type C — Process Diagram FIG 8.6-B Protocol Demultiplexing — Parsing Eth→IP→TCP→HTTP from Raw Bytes
Protocol demultiplexing — how a packet analyzer identifies and parses each protocol layer from raw bytes. The EtherType field in the Ethernet header determines the next parser (0x0800 = IPv4, 0x0806 = ARP, 0x86DD = IPv6). The Protocol field in the IPv4 header selects the Layer 4 parser (6 = TCP, 17 = UDP, 1 = ICMP). The TCP/UDP destination port number suggests the application layer protocol (80 = HTTP, 443 = HTTPS, 53 = DNS). A packet analyzer implements this as a chain of parser functions, each reading its header and dispatching to the next layer's parser. Wireshark implements hundreds of protocol dissectors using this exact architecture.
Type D — Reference Diagram FIG 8.6-C pcap File Format — Global Header + Per-Packet Records
The pcap file format (used by Wireshark, tcpdump, and virtually all network analysis tools). The 24-byte global header identifies the file (magic number for endianness detection), the pcap version, the maximum captured bytes per packet (snaplen), and the link-layer type (1 = Ethernet, 105 = 802.11 Wi-Fi). Each captured packet is stored as a 16-byte per-packet header — Unix timestamp in seconds and microseconds, number of bytes captured (may be less than original if truncated by snaplen), and original packet length — followed by the raw captured bytes. Reading a pcap file is straightforward: parse the global header once, then loop reading per-packet headers and their corresponding data. This is the starting point for building a packet analyzer in Python using only the struct module.
