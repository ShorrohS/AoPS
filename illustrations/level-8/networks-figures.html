Type A — Chapter Hero FIG 8-A Network Layer Stack — From Physical Bits to Application Data
The network layer stack. Each layer adds its header when sending (encapsulation) and removes it when receiving (decapsulation). Application layer: HTTP request "GET / HTTP/1.1". Transport layer (TCP): adds source/destination port numbers, sequence numbers, and reliability mechanisms. Network layer (IP): adds source/destination IP addresses for routing across networks. Data Link (Ethernet): adds MAC addresses for delivery on the local network. Physical: actual electrical or radio signals. A web request traverses all seven layers twice — down on the client, up on the server.
Type D — Process Diagram FIG 8-B DNS Resolution — How a Hostname Becomes an IP Address
DNS resolution is a hierarchical lookup. The browser checks its local cache (steps are skipped if cached). The OS resolver queries its configured DNS server (e.g. 8.8.8.8). The resolver works up the hierarchy: asks the Root nameserver which server handles .com, asks the .com TLD server which server handles example.com, then asks the authoritative nameserver for the A record. The IP address is returned and cached for the TTL duration. Typical DNS resolution takes 20–100ms on the first request; sub-millisecond from cache. This 8-step dance happens for every new hostname — which is why DNS caching is critical for web performance.
