Module 8.3 — Transport Layer: TCP and UDP

Type A — Chapter Hero FIG 8.3-A TCP Three-Way Handshake — SYN, SYN-ACK, ACK
TCP three-way handshake establishes the connection and synchronises Initial Sequence Numbers (ISNs) on both sides. Step 1: Client sends SYN with its ISN (100). Step 2: Server responds with SYN-ACK — its own ISN (300) and acknowledgement of the client's ISN+1 (101). Step 3: Client sends ACK acknowledging the server's ISN+1 (301). Now both sides know each other's sequence numbers, enabling reliable ordered delivery. The handshake costs one full round-trip before any data transfers — at 100ms RTT, this adds 100ms latency to every new TCP connection. HTTP/1.1 persistent connections amortise this cost; HTTP/3 over QUIC achieves 0-RTT reconnection using session tickets.
Type C — Process Diagram FIG 8.3-B TCP Sliding Window — Flow Control in Action
TCP sliding window flow control. Rather than waiting for an ACK after each segment (stop-and-wait), TCP allows the sender to have a window of unacknowledged segments in flight simultaneously. The receiver's advertised window size tells the sender its available buffer space. When the sender receives ACK 3, segment 3 is confirmed received; the window slides right, freeing a slot for segment 8. Maximum throughput is bounded by window_size / RTT — at 100ms RTT and 64KB window the theoretical maximum is about 5 Mbps. TCP congestion control (AIMD — Additive Increase Multiplicative Decrease) dynamically adjusts the window based on network conditions, preventing congestion collapse.
Type D — Reference Table FIG 8.3-C TCP vs UDP — When to Use Which Transport Protocol
Transport protocol selection guide. TCP's reliability machinery — sequence numbers, acknowledgements, retransmission, flow control, and congestion control — makes it the right choice whenever every byte must arrive correctly: HTTP, file transfer, database connections. UDP's minimal header (8 bytes vs TCP's 20+) and lack of handshake overhead make it right for latency-sensitive applications where occasional packet loss is acceptable or managed by the application. DNS uses UDP because queries fit in one packet and the application simply retries. Modern video streaming uses UDP because a retransmitted old video frame would arrive too late. HTTP/3 uses QUIC — a reliability protocol built on top of UDP — to combine reliability with better multiplexing than TCP, eliminating TCP's head-of-line blocking problem.
