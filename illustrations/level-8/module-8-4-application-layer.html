Type A — Chapter Hero FIG 8.4-A DNS Resolution — How "example.com" Becomes an IP Address
DNS resolution chain for "example.com". The stub resolver in your OS contacts the recursive resolver (typically your ISP's or a public resolver like 8.8.8.8). If the answer is not cached, the recursive resolver queries the root nameservers, which direct it to the .com TLD nameservers. The TLD nameservers provide the address of example.com's authoritative nameserver (ns1.example.com). The authoritative nameserver holds the A record — the actual IP address (93.184.216.34) with a TTL indicating how long it may be cached. The recursive resolver returns the IP to your device. The entire chain typically completes in 50–200ms on first lookup; subsequent lookups return from cache in under 1ms.
Type E — Comparison FIG 8.4-B HTTP/1.1 vs HTTP/2 vs HTTP/3 — Connection Model Evolution
HTTP version evolution driven by latency and throughput problems. HTTP/1.1 serialises requests on a persistent connection — the browser hacks around this by opening up to 6 connections per host. HTTP/2 introduces multiplexing: multiple request/response streams share one TCP connection via framing, eliminating the need for multiple connections. However, a single lost TCP segment blocks all streams (TCP head-of-line blocking). HTTP/3 over QUIC runs over UDP with independent streams at the transport layer — a lost UDP packet only blocks the stream that owns it. QUIC also incorporates TLS 1.3 into the handshake, achieving 1-RTT initial connection and 0-RTT reconnection for known servers.
Type B — Reference Diagram FIG 8.4-C URL Anatomy — Every Component of a Web Address
URL (Uniform Resource Locator) anatomy. The scheme identifies the protocol. Userinfo (rarely used in HTTP — credentials belong in headers, not URLs). Host is resolved via DNS. Port defaults to 443 for HTTPS and 80 for HTTP if omitted. Path identifies the resource on the server. Query string passes parameters to the server (sent in the HTTP request line). The fragment identifier (#section) is processed entirely by the browser — it is never transmitted to the server, making it useful for client-side navigation in single-page applications. URLs must percent-encode characters outside the allowed ASCII subset: space becomes %20, @ becomes %40.
