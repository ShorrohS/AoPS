Module 10.2 — How Browsers Render Pages

Type A — Chapter Hero FIG 10.2-A Browser Rendering Pipeline — HTML to Pixels in 6 Steps
The browser rendering pipeline from HTML bytes to pixels on screen. HTML parsing builds the DOM tree; CSS parsing builds the CSSOM. They are merged into the Render Tree (only visible nodes with computed styles). Layout calculates the exact position and size of every element (reflow). Paint fills pixels into layers (repaint). Composite blends GPU layers onto screen. To maintain 60fps, all stages must complete within 16.6ms per frame. The critical performance insight: CSS transform and opacity changes skip Layout and Paint entirely — they only trigger Compositing, which runs on the GPU. Animating these properties is "free" compared to animating width or top, which force full reflows.
Type B — Concept Diagram FIG 10.2-B DOM Tree — HTML Parsed into a JavaScript-Accessible Object Tree
The Document Object Model (DOM) is the browser's object representation of the parsed HTML. Every element becomes a node with properties (id, className, textContent) and methods (querySelector, appendChild). JavaScript navigates and mutates the DOM at runtime — changing a node's text content, adding/removing classes, or inserting new elements. Every mutation that affects layout or appearance triggers the rendering pipeline: a geometry change triggers reflow, a style change triggers repaint. Batching DOM mutations (document fragment, virtual DOM in React) reduces pipeline re-triggers. The DOM is also what makes accessibility work — screen readers traverse the DOM tree to understand page structure.
Type D — Process Diagram FIG 10.2-C Critical Rendering Path — What Blocks First Paint
The critical rendering path — the sequence of steps the browser must complete before showing any pixels. CSS stylesheets are render-blocking: the browser cannot paint until it has built the CSSOM (a script might query computed styles). Synchronous <script> tags are parser-blocking: the HTML parser stops, the script is fetched and executed, then parsing resumes. To optimise: place CSS <link> in <head> (not blocking by position, but must complete before paint), use <script defer> for non-critical scripts (parsed and loaded in background, executed in order after HTML is fully parsed), and use <link rel="preload"> to hint the browser to fetch critical assets early. The goal is First Contentful Paint (FCP) under 1.8 seconds on a 4G mobile connection.
