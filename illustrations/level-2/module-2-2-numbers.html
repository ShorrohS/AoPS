Type A — Chapter Hero FIG 2.2-A Positional Notation — The Same Number in Four Bases
The number 42 expressed in four positional bases. Decimal (base 10): 4×10 + 2×1 = 42. Binary (base 2): 1×32 + 0×16 + 1×8 + 0×4 + 1×2 + 0×1 = 42, written 0b101010. Octal (base 8): 5×8 + 2×1 = 42, written 0o52 — each octal digit corresponds to exactly 3 binary bits. Hexadecimal (base 16): 2×16 + 10×1 = 42, written 0x2A — each hex digit corresponds to exactly 4 binary bits, making hex a compact notation for binary data.
Type C — Concept Diagram FIG 2.2-B Two's Complement — Representing Negative Numbers in Binary
Two's complement representation. Left: the 4-bit integer number line arranged in a circle. Positive values (0–7) have sign bit 0. Negative values (−1 to −8) have sign bit 1, with −8 as the only asymmetric value. Right: negation procedure for 8-bit +42. Step 1: invert all bits (bitwise NOT). Step 2: add 1. Verification: adding +42 and −42 produces 0 with a carry bit that is discarded. The key insight is that subtraction becomes addition — A − B = A + (−B) — so CPUs only need one arithmetic unit for both operations.
Type D — Process Diagram FIG 2.2-C Binary Addition with Carry — Column-by-Column
Binary addition of 183 (0b10110111) and 105 (0b01101001). Carries are shown in red above each column. The result 288 exceeds 8-bit capacity (max 255), so the final carry-out is set and the stored result wraps to 32 (0b00100000 = 288 − 256). The processor's Carry Flag (CF) is set to 1, alerting software that overflow has occurred. Eight addition rules cover all cases; a CPU's adder circuit implements exactly this truth table in hardware.
