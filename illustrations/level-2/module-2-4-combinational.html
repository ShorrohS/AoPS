Type A — Chapter Hero FIG 2.4-A Half Adder → Full Adder — Adding Bits with Gates
Half adder (left) and full adder (right). The half adder adds two 1-bit inputs using XOR (sum) and AND (carry out) — no carry input. The full adder extends this by chaining two half adders with an OR gate. It accepts three inputs: A, B, and a carry-in (Cin) from the previous column. The carry-out is generated by ORing the carry outputs of both half adders. Full adders can be chained to add multi-bit numbers — four full adders build a 4-bit ripple carry adder.
Type F — Simulation Figure FIG 2.4-B 4-Bit Ripple Carry Adder — Carry Propagation Chain
4-bit ripple carry adder computing 0111 + 0001 = 1000 (7 + 1 = 8). Each full adder processes one bit column with a carry-in from the previous. The carry propagates through all four stages — bit 0 generates carry 1, which propagates through bits 1 and 2 (producing sum 0 each time), until bit 3 produces the final sum bit 1. The "ripple" refers to this sequential carry propagation: the adder cannot produce the final result until all carries have settled. This O(n) delay motivated the invention of carry lookahead adders, which compute all carries in parallel in O(log n) time.
Type C — Process Diagram FIG 2.4-C Multiplexer and Decoder — Selecting and Routing Binary Data
Two fundamental combinational building blocks: the multiplexer (MUX) and the decoder. A 4-to-1 MUX routes one of four data inputs to a single output, selected by two control lines — used in CPU datapaths to choose between ALU operands. A 2-to-4 decoder converts a 2-bit binary address into four one-hot outputs (exactly one high at a time) — used in memory address decoding to select which memory bank or register to activate. Both circuits appear repeatedly at every level of computer architecture.
