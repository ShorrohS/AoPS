Type A — Chapter Hero FIG 11.1-A State Space Search — BFS, DFS, and A* on a Grid Maze
State space search on a 5×5 grid maze. BFS (left) expands all cells at distance 1, then 2, then 3 — guaranteeing the shortest path but exploring many irrelevant cells. A* (right) uses a heuristic function f(n) = g(n) + h(n): the actual cost to reach n plus an estimate of the remaining cost (Manhattan distance to goal). By always expanding the node with lowest f(n), A* focuses exploration toward the goal and visits far fewer cells. A* is optimal when the heuristic is admissible (never overestimates the true remaining cost). Real applications: Google Maps routing (Dijkstra/A* on road graphs), game pathfinding (A* on grids), robot motion planning (configuration space search).
Type C — Process Diagram FIG 11.1-B Minimax Game Tree — Two-Player Zero-Sum Search
Minimax game tree for a two-player zero-sum game. MAX (AI) wants to maximise the score; MIN (opponent) wants to minimise it. At leaf nodes, a static evaluation function scores the position. Values propagate upward: MIN nodes take the minimum of their children (opponent plays best), MAX nodes take the maximum (AI plays best). The root's value (3) is MAX's guaranteed score with perfect play. Alpha-Beta pruning eliminates branches that cannot affect the final decision — if the MIN node has already found a value of 2 and the MAX parent already has 3, exploring further subtrees of that MIN node is unnecessary. This reduces the effective branching factor from b to √b, enabling chess engines to search millions of positions per second.
Type D — Process Diagram FIG 11.1-C Constraint Satisfaction — N-Queens Backtracking Search
Constraint satisfaction with N-Queens backtracking. For each row, try placing a queen in each column. After each placement, check all constraints (no shared row, column, or diagonal with any previously placed queen). If no valid column exists in the current row, backtrack to the previous row and try the next column there. The 4-Queens solution [1,3,0,2] places queens at (row 0, col 1), (row 1, col 3), (row 2, col 0), (row 3, col 2). Backtracking prunes the search tree dramatically — the naive approach would check 4⁴ = 256 configurations; backtracking discovers the solution in about 20 checks. Constraint propagation (forward checking, arc consistency) reduces the search further by eliminating values that provably cannot lead to solutions.
