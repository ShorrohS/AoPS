Module 7.4 — Building a Shell

Type A — Chapter Hero FIG 7.4-A Shell Internals — The Read-Parse-Fork-Exec-Wait Cycle
The shell's core loop: read a line from the terminal, tokenise and parse it into a command and arguments, fork a child process (an identical copy of the shell), call exec in the child (replacing the child's memory image with the requested program), then wait for the child to finish before printing the next prompt. The shell itself is never replaced — it always returns to the top of the loop. This fork-exec separation is elegant: between fork() and exec(), the child can redirect file descriptors, set environment variables, or set up pipes — before the new program ever starts. This is how shell redirection (>, <, |) is implemented.
Type C — Process Diagram FIG 7.4-B fork() / exec() / wait() — Process Tree After Each System Call
The fork/exec/wait triad is the foundation of Unix process creation. fork() duplicates the calling process — both parent and child continue after the fork call, distinguished by the return value (0 in child, child PID in parent). exec() replaces the calling process's memory image with a new program — the PID is preserved but everything else changes. The parent calls waitpid() which suspends it until the child exits, preventing zombie processes. The crucial architectural insight: the gap between fork() and exec() lets the child rearrange its file descriptors (enabling redirection with dup2()) and set up pipe endpoints before the new program starts — without any cooperation from the new program itself.
Type D — Process Diagram FIG 7.4-C Shell Pipeline — ls | grep txt | wc -l
Shell pipeline ls | grep txt | wc -l implemented with two kernel pipes and three child processes. The shell calls pipe() twice to create two kernel pipe file descriptors, then forks three children. Before each child calls exec(), it uses dup2() to redirect: ls's stdout to pipe1's write end, grep's stdin from pipe1's read end and stdout to pipe2's write end, wc's stdin from pipe2's read end. All three processes run concurrently — ls writes output as grep reads it, grep filters and writes as wc reads. The kernel pipe buffer (typically 64KB) decouples their speeds. The shell waits for all three children to exit, then prints the next prompt. This is the Unix philosophy in hardware: small programs connected by pipes, with the kernel's pipe primitive doing all the work.
