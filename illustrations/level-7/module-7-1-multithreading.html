Type A — Chapter Hero FIG 7.1-A Threads vs Processes — Shared Memory vs Isolated Address Spaces
The fundamental distinction between processes and threads. Each process receives its own isolated virtual address space — process A cannot access process B's memory; communication requires explicit IPC (pipes, sockets, shared memory segments). Threads within a single process share the heap, global data, open file descriptors, and code segment — any thread can read or write any shared variable instantly. This sharing is both the strength (cheap communication, low creation cost) and the hazard (race conditions when multiple threads write the same location without synchronisation). Thread creation is ~10× cheaper than process creation; context switching between threads is ~3× faster than between processes.
Type C — Process Diagram FIG 7.1-B Race Condition — Two Threads Incrementing a Counter
Race condition on a shared counter. The C expression counter++ compiles to three machine instructions: READ (load counter into register), ADD (increment register), WRITE (store register back). When Thread A and Thread B interleave — both reading the value 0 before either writes back — both compute 0+1=1 and write 1. The second write overwrites the first, losing one increment entirely. The expected final value is 2 but the actual result is 1. This is a lost update. The fix is a mutex: only one thread at a time may execute the read-add-write sequence (the critical section). Alternatively, atomic hardware instructions (LOCK XADD on x86) perform the three-step operation indivisibly.
Type D — Simulation Figure FIG 7.1-C CPU Thread Scheduling — Time-Slice Context Switching
Preemptive time-slice scheduling with three threads on a single CPU. The OS scheduler allocates 10ms quanta, cycling through runnable threads. When Thread 2 blocks on I/O at t=40ms, the CPU immediately switches to Thread 3 — no busy-waiting. Thread 2 is moved to the WAITING state and only returns to READY when the I/O interrupt fires (at ~t=65ms), resuming in the next available slot. Context switching saves and restores the entire thread state (registers, program counter, stack pointer) from the Thread Control Block. The illusion of simultaneous execution emerges from rapid switching — at 10ms quanta, three threads appear to run in parallel to a human observer.
