Type A — Chapter Hero FIG 7.5-A HTTP/1.1 Request and Response — Anatomy of Every Web Transaction
HTTP/1.1 request and response anatomy. Both are plain text transmitted over a TCP connection. A request opens with a request line (method, path, HTTP version), followed by headers (key: value pairs), a mandatory blank line, then an optional body (present in POST/PUT). The response opens with a status line (version, numeric code, reason phrase), then headers, blank line, body. The blank line (CRLF CRLF) is the delimiter between headers and body — a server must read until it finds this sequence before parsing headers. HTTP is intentionally human-readable, which makes debugging with nc or telnet trivial.
Type E — Comparison FIG 7.5-B HTTP Server Models — Single-Threaded, Multi-Threaded, Event-Driven
Three HTTP server concurrency models. Single-threaded is simple but blocks on I/O — second request waits for first. Thread-per-request handles concurrent I/O but costs ~1MB of stack RAM per thread: at 10,000 concurrent connections that is 10GB RAM just for stacks. The event-driven model (Nginx, Node.js) uses a single thread with epoll/kqueue to monitor thousands of file descriptors simultaneously — the thread only runs when a descriptor is ready, eliminating idle time. This solved the "C10K problem" (10,000 simultaneous connections on a single server) in the early 2000s. Modern servers combine: a thread pool matching CPU cores, each running an event loop.
Type D — Process Diagram FIG 7.5-C HTTP Request Processing Pipeline — accept to response
HTTP server request processing pipeline. accept() blocks until a new TCP connection arrives, returning a connected socket file descriptor. read() collects bytes until the CRLF-CRLF header terminator. parse() extracts method, path, HTTP version, and all headers. route() looks up the path in a routing table to find the appropriate handler function. handler() performs the application logic — reading a file, querying a database, calling another service. write() serialises the response (status line, headers, blank line, body) and sends it over the socket. Any stage can short-circuit with an error response: a malformed request returns 400, an unknown path returns 404, an unhandled exception returns 500.
