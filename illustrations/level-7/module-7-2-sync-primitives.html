Type A — Chapter Hero FIG 7.2-A Mutex — Protecting a Critical Section from Concurrent Access
Mutex (mutual exclusion lock) protecting a critical section. Thread A calls mutex_lock(), acquires the lock (mutex transitions to LOCKED), and enters the critical section. When Thread B calls mutex_lock() while the mutex is held by A, the OS suspends B — it moves to WAITING state and stops consuming CPU. When A calls mutex_unlock(), the OS wakes B, which then acquires the lock and executes its own critical section. The two increments now happen sequentially — no interleaving — and the final counter is the correct value 2. The mutex guarantees mutual exclusion (only one thread in the critical section at a time) but not ordering. pthreads: pthread_mutex_lock/unlock. C++: std::mutex with std::lock_guard.
Type B — Concept Diagram FIG 7.2-B Deadlock — Circular Wait: Two Threads, Two Mutexes
Deadlock arising from circular wait: Thread A holds Mutex M1 and waits for M2; Thread B holds M2 and waits for M1. Neither can proceed — they wait forever. Deadlock requires four Coffman conditions simultaneously: mutual exclusion (only one thread can hold a lock), hold-and-wait (holding a lock while waiting for another), no preemption (locks cannot be forcibly taken), and circular wait. Breaking any one condition prevents deadlock. The simplest prevention: impose a global lock ordering — all threads must acquire M1 before M2. This eliminates circular wait by construction. Tools like ThreadSanitizer (TSan) detect potential deadlocks dynamically.
Type D — Process Diagram FIG 7.2-C Semaphore — Producer-Consumer with Bounded Buffer
Bounded-buffer producer-consumer using two semaphores and one mutex. Semaphore empty (initialised to N) counts available slots — the producer decrements it before adding; if empty=0, the producer blocks. Semaphore full (initialised to 0) counts available items — the consumer decrements it before removing; if full=0, the consumer blocks. A mutex protects the actual buffer operations from concurrent access. This classic synchronisation pattern appears in operating system I/O buffers, message queues, thread pool task queues, and network socket receive buffers. Two semaphores handle the bounded capacity; the mutex handles mutual exclusion — each solves a different problem.
