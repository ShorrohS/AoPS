Module 4.4 — Memory Management
2 figures · Virtual Memory Address Space · Page Table Translation
Type A — Chapter Hero FIG 4.4-A Virtual Memory — Every Process Gets Its Own 48-bit Address Space
Virtual memory gives each process a private, contiguous-looking address space regardless of where its pages actually live in physical RAM. Both Process A and Process B see the same virtual address layout (kernel at top, stack below, heap above code). The MMU (Memory Management Unit) hardware — guided by each process's page table — transparently translates every virtual address to a physical frame address. Physical frames are scattered and interleaved between processes with no visible correlation to virtual addresses. A process cannot access another process's frames because it has no valid page table entries pointing to them — attempts cause a page fault (segmentation fault in user terms).
Type C — Process Diagram FIG 4.4-B Virtual Address Translation — 2-Level Page Table Walk
Two-level page table walk for virtual-to-physical address translation. The 32-bit virtual address is split into three fields: a 10-bit Page Directory index, a 10-bit Page Table index, and a 12-bit byte offset (supporting 4KB pages). The MMU uses CR3 to find the Page Directory, reads the entry at PD[1] to locate the Page Table at physical address 0x2000, then reads PT[3] to find the physical page frame at 0xD000. Adding the offset (0x010) gives the final physical address 0xD010. The Translation Lookaside Buffer (TLB) caches recent translations to avoid this expensive two-memory-access walk on every instruction.
Type B — Concept Diagram FIG 4.4-C Segmentation Fault — Accessing a Non-Mapped Virtual Address
The anatomy of a segmentation fault, explained from hardware upward. Every process has a virtual address space divided into mapped regions (stack, heap, code, data) and unmapped regions. When a program accesses an address in an unmapped region — the classic case being a null pointer dereference — the MMU finds no valid page table entry and raises a hardware Page Fault exception. The OS kernel handles this fault: if the address should be in swap space, it loads the page from disk (a valid soft fault). If the address is truly unmapped, the kernel sends SIGSEGV to the process, which terminates it. Virtual memory hardware is what makes this safe containment possible.
