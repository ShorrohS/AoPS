Type A — Chapter Hero FIG 4.3-A Kernel vs Userspace — The Protected Boundary
Kernel vs userspace separation. User space (top) runs with restricted CPU privileges (Ring 3 on x86) — processes cannot directly access hardware, other processes' memory, or kernel data structures. Kernel space (bottom) runs at Ring 0 with full hardware access. The system call interface is the only sanctioned crossing point: user code executes SYSCALL, the CPU switches to Ring 0, the kernel handles the request, then returns to Ring 3. This enforced boundary is the fundamental security and stability mechanism of modern OSes — a buggy user program cannot corrupt the kernel or other processes.
Type D — Process Diagram FIG 4.3-B Process Lifecycle and Context Switching
Process lifecycle states and transitions. NEW: process created by fork()/exec(). READY: waiting in the scheduler queue for CPU time. RUNNING: actively executing on a CPU core. WAITING/BLOCKED: suspended waiting for I/O completion, a lock, or a timer. EXIT: process has returned or called exit(). Context switching (gold annotation) occurs at preemption boundaries — the scheduler saves the running process's complete CPU state (all registers, PC, flags) into its Process Control Block, then restores the next process's state from its PCB. This creates the illusion of simultaneous execution across multiple processes on a single core.
Type C — State Diagram FIG 4.3-C Process Lifecycle — Five-State Model
The five-state process lifecycle model used by most operating system schedulers. A process is created in the NEW state via fork(). It enters the READY queue waiting for CPU time. The scheduler dispatches it to RUNNING when a CPU core is available. If the time quantum expires or a higher-priority process arrives, it is preempted back to READY. If the running process requests I/O, it moves to WAITING until an interrupt signals the I/O is complete, whereupon it returns to READY. Finally, exit() moves it to TERMINATED and releases its Process Control Block. This model is implemented in Linux, Windows, and macOS — billions of state transitions occur every second on a busy server.
