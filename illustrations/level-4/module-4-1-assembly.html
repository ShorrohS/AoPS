Type A — Chapter Hero FIG 4.1-A The Compilation Pipeline — Source Code to Running Program
The complete compilation pipeline for a C program. The compiler (gcc -S) translates C source into x86-64 assembly mnemonics. The assembler (as) converts each mnemonic into its byte encoding — PUSH RBP becomes 0x55, MOV RBP,RSP becomes 0x48 0x89 0xE5. The linker (ld) combines object files with library stubs, resolves symbol references, and produces an ELF executable with sections for code (.text), initialised data (.data), read-only data (.rodata), and others. The OS exec() call loads the executable into virtual memory and creates the process. The stack and heap grow dynamically at runtime.
Type C — Concept Diagram FIG 4.1-B Assembly Instruction Anatomy — Opcode, Operands, Addressing Modes
Assembly instruction structure. Every instruction has an opcode (operation code) and zero or more operands. MOV EAX, 42 loads the value 42 into register EAX using immediate addressing — the value is embedded in the instruction bytes (0xB8 0x2A 0x00 0x00 0x00). ADD EAX, EBX uses register-register addressing — fastest possible, no memory access needed. MOV EAX, [RBX + RCX*4 + 8] uses the most complex x86-64 addressing mode: base register + index register × scale factor + displacement, all in one instruction. Assembly is the lowest readable representation before machine code bytes.
Type C — Process Diagram FIG 4.1-C Compilation Pipeline — From C Source to Running Machine Code
The four-stage C compilation pipeline. The preprocessor (cpp) expands #include directives and macros, producing an intermediate .i file. The compiler (cc1) translates to human-readable assembly (.s). The assembler (as) encodes assembly mnemonics as binary machine code, producing a relocatable object file (.o) with unresolved symbol references (marked ?? for the printf call address). The linker (ld) resolves all symbol references by combining object files with library code, filling in the correct addresses and producing the final self-contained executable.
