Type A — Chapter Hero FIG 6.6-A Graph Representations — Adjacency Matrix vs Adjacency List
The same undirected 4-node graph stored two ways. The adjacency matrix is a V×V boolean grid — O(1) edge existence check but O(V²) space regardless of edge count. The adjacency list stores only actual edges per node — O(V+E) space, O(degree) to iterate neighbours. For a social network with 1 billion users and 100 billion friendships (average degree 100), the list uses ~800 GB while the matrix would require 1 billion² bits ≈ 10^18 bytes — physically impossible. Adjacency lists are the universal choice for graph algorithms; matrices appear in dense graphs like fully-connected neural network layers.
Type E — Comparison FIG 6.6-B BFS vs DFS — Traversal Order on the Same Graph
BFS (queue-based) explores level by level, guaranteeing it finds the shortest path in unweighted graphs — critical for social network degree separation, web crawlers, and GPS routing. DFS (stack-based, or recursive) plunges as deeply as possible before backtracking, naturally discovering connected components, topological ordering of dependencies, and strongly connected components (Tarjan's algorithm). Both run O(V+E) with an adjacency list. The choice is driven by the problem: shortest path → BFS; topological sort, cycle detection, maze → DFS.
Type D — Process Diagram FIG 6.6-C Dijkstra's Shortest Path — Step-by-Step on a Weighted Graph
Dijkstra's shortest path algorithm traced on a 4-node weighted graph. The priority queue (min-heap) always extracts the node with the smallest tentative distance. When node C (dist=2) is extracted, it updates D's distance to 3 via the C→D edge of weight 1 — cheaper than the direct A→B→D path of weight 4+5=9. The algorithm's correctness relies on non-negative edge weights: once a node is extracted from the priority queue, its distance is provably minimal. For negative weights, Bellman-Ford is needed instead. Real-world use: Google Maps, network routing (OSPF), game pathfinding.
