Type A — Chapter Hero FIG 6.2-A Stack (LIFO) vs Queue (FIFO) — Structural Comparison
Stack and Queue are the two fundamental access-ordered data structures. A Stack enforces Last-In-First-Out (LIFO): push adds to the top, pop removes from the top. A Queue enforces First-In-First-Out (FIFO): enqueue adds to the rear, dequeue removes from the front. Both operations are O(1) regardless of structure size when implemented with a linked list or circular buffer. The key distinction is the relationship between insertion order and retrieval order — stacks reverse it, queues preserve it.
Type C — Process Diagram FIG 6.2-B Stack Applications — Call Stack, Undo/Redo, Expression Evaluation
Three canonical stack applications. The function call stack tracks activation frames — each function call pushes a frame containing local variables and the return address; return pops the frame and resumes the caller. Undo/redo systems maintain two stacks: Ctrl+Z pops from the undo stack and pushes onto the redo stack; Ctrl+Y reverses this. Postfix (Reverse Polish Notation) expression evaluation uses a single stack — operands are pushed, operators pop their operands, compute, and push the result. All three rely on LIFO order as a correctness requirement, not an optimisation.
Type D — Reference Table FIG 6.2-C Queue Applications — BFS Frontier, Task Scheduling, Print Queue
Three canonical queue applications. BFS uses a queue as its frontier — visited nodes' unvisited neighbours are enqueued, ensuring nodes are explored in order of increasing distance from the source, which guarantees shortest-path correctness on unweighted graphs. Round-robin CPU scheduling rotates processes through the ready queue, giving each a time slice in arrival order for fair CPU sharing. Print spoolers queue jobs in submission order so no document is skipped. All three require FIFO ordering as a correctness invariant, not merely a convenience.
