Type A — Chapter Hero FIG 6B-A Sorting Algorithm Comparison — Bubble vs Merge vs Quick
Three sorting algorithms on 7 elements. Bubble Sort (O(n²)): repeatedly compare adjacent pairs and swap — the maximum "bubbles" to the right on each pass. Simple but impractical: 1000 elements require ~500,000 comparisons. Merge Sort (O(n log n)): recursively split into halves, sort each half, merge back — guaranteed n log n at all times but requires O(n) extra memory. Quick Sort (O(n log n) average): choose a pivot, partition around it, recurse on each partition — fastest in practice due to cache efficiency, but O(n²) worst case on sorted input with naive pivot selection. Production sort implementations (C++ std::sort, Python timsort) use hybrid strategies to avoid worst cases.
Type C — Concept Diagram FIG 6B-B BFS vs DFS — Two Graph Traversal Strategies
BFS vs DFS traversal of the same tree. BFS (left, green): uses a Queue — dequeue a node, process it, enqueue all its unvisited neighbours. This processes all nodes at distance 1, then all at distance 2, etc. Guarantees the shortest path in unweighted graphs. DFS (right, red): uses a Stack (or recursion) — push a node, process it, push its first unvisited neighbour immediately. Goes as deep as possible before backtracking. Both are O(V+E) time. BFS uses O(V) space for the queue (wide graphs are expensive). DFS uses O(h) stack space where h is the tree height (tall/deep graphs are expensive). Choice depends on the problem: shortest path → BFS; maze solving, topological sort, cycle detection → DFS.
Type C — Concept Diagram FIG 6B-C Big-O Growth Curves — Why Complexity Matters at Scale
Big-O growth curves on a log-log scale. O(1) is horizontal — constant time regardless of input. O(log n) grows barely at all — doubling the input only adds one step. O(n) grows proportionally — twice the data, twice the time. O(n log n) is slightly worse but acceptable for large inputs (merge sort on a million items: ~20 million operations). O(n²) becomes unusable at scale: a million items need a trillion operations. O(2ⁿ) (exponential) shoots off the chart almost immediately — viable only for n < 30. Choosing an algorithm is choosing a curve; at n=10,000 the difference between O(n²) and O(n log n) is 10,000,000 vs 133,000 — a 75× difference that compounds rapidly.
