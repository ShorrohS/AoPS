Type A — Chapter Hero FIG 6.5-A Max-Heap — Tree View and Array Representation Side by Side
A max-heap of 7 elements stored as a 1-indexed array. The heap property (every node ≥ its children) guarantees the maximum is always at index 1, accessible in O(1). Parent-child relationships are computed arithmetically: parent(i) = ⌊i/2⌋, left(i) = 2i, right(i) = 2i+1 — no pointers required. This array-backed representation makes heaps extremely cache-efficient compared to pointer-based trees: all elements occupy a contiguous memory block, and accessing a child is a multiply-by-two rather than a pointer dereference. The complete binary tree shape (filled level by level) guarantees height = ⌊log₂ n⌋, bounding all operations to O(log n).
Type C — Process Diagram FIG 6.5-B Heap Insert (Sift-Up) and Extract-Max (Sift-Down)
Heap insert (sift-up) and extract-max (sift-down). Insert appends the new element at the next array position, then bubbles it up by repeatedly swapping with its parent while it is larger — at most ⌊log₂ n⌋ swaps. Extract-max removes the root (the maximum), moves the last element to the root position to maintain the complete tree shape, then sifts it down by swapping with the larger of its two children — until the heap property is restored. Both operations cost O(log n) — the key insight that makes heaps useful for priority queues where push and pop-max must both be fast.
Type D — Application Diagram FIG 6.5-C Priority Queue Applications — Dijkstra, Task Scheduling, Heapsort
Three canonical priority queue applications, all powered by the heap. Dijkstra's shortest path algorithm uses a min-heap keyed by tentative distance — always extracting the nearest unvisited node ensures correctness. OS task schedulers maintain a priority queue of runnable tasks — the CPU always executes the highest-priority task, with O(log n) insert when new tasks arrive and O(log n) extract when the current task yields. Heapsort builds a max-heap in O(n), then repeatedly extracts the maximum to the end of the array — producing a sorted result in O(n log n) worst-case with O(1) extra space, unlike merge sort's O(n) auxiliary array.
