Type A — Chapter Hero FIG 6.1-A Array vs Linked List — Memory Layout Comparison
Array vs linked list memory layout. Arrays store elements at consecutive addresses — index i is found by one multiply-and-add: base + i×size, giving O(1) random access. Linked list nodes are scattered anywhere in the heap, connected by pointers. Accessing element i requires following i pointers from the head — O(n). However, inserting or deleting in a linked list only requires updating two pointers — O(1) once the position is known. The fundamental trade-off: arrays are fast to read, linked lists are fast to modify structurally.
Type C — Process Diagram FIG 6.1-B Linked List Insert and Delete — Pointer Manipulation
Linked list pointer manipulation for insert and delete. Inserting a new node between A and B requires exactly two pointer updates: new_node.next = A.next, then A.next = new_node — no element shifting, no reallocation, O(1). Deleting node B requires one update: A.next = B.next — then free B's memory. The critical caveat: both operations require knowing the predecessor node. Finding that predecessor still costs O(n) traversal from the head. Doubly-linked lists add a prev pointer to each node, enabling O(1) delete given only the node itself.
Type D — Reference Table FIG 6.1-C Array vs Linked List — Operation Complexity Summary
Operation complexity table for arrays, singly linked lists, and doubly linked lists. The doubly linked list achieves O(1) delete when given a direct node reference because each node knows its predecessor through prev. Arrays achieve O(1) append amortized — dynamic arrays (Python list, C++ vector) occasionally resize by doubling capacity, but the average cost per append over N operations is O(1). The practical choice depends on the dominant operation: favour arrays for indexed reads, favour doubly linked lists for frequent arbitrary insertions and deletions.
