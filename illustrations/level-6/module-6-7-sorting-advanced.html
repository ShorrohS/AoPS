Type A — Chapter Hero FIG 6.7-A Quicksort Partition Step — Lomuto Scheme with Pivot = Last Element
Quicksort's partition step using the Lomuto scheme with the last element as pivot. The algorithm scans with index j; whenever an element ≤ pivot is found, it swaps into the "≤ pivot" region (tracked by i). After the scan, the pivot is placed at i+1 — its final sorted position. The partition takes O(n) and splits the array into two subproblems. Key insight: the pivot's final position is determined in a single linear pass, and the two sub-arrays are then sorted recursively. With a good pivot choice (random or median-of-3), the expected split is near 50/50, giving O(n log n) average. A terrible pivot (always smallest or largest) produces O(n²).
Type E — Comparison FIG 6.7-B Quicksort Recursion Tree — Balanced (Best) vs Skewed (Worst)
Quicksort's two extremes. With a median pivot, each partition splits evenly into n/2 + n/2, producing log₂ n levels — at each level the total work is n (all partitions at that depth sum to n elements). Total: O(n log n). With the minimum element always chosen as pivot, partitions split into 0 + (n−1) — a degenerate chain of n levels. Total work: n + (n−1) + ... + 1 = O(n²). This worst case hits exactly when a sorted array is partitioned using the last element as pivot — a fatal interaction. The fix: choose a random pivot, or the median of the first, last, and middle elements. Production Quicksort implementations (introsort in C++ STL, Timsort in Python) use these strategies plus heapsort fallback.
Type D — Process Diagram FIG 6.7-C Radix Sort (LSD) — Sorting Integers Digit by Digit
Radix sort (Least Significant Digit) sorts integers one digit position at a time, using a stable sub-sort (counting sort) at each pass. After pass 1 (units), numbers are grouped by their last digit. After pass 2 (tens), the relative order within each tens-group is already correct from pass 1 — stability is essential. After pass 3 (hundreds), the array is fully sorted. The algorithm never compares elements — it only examines individual digits — breaking through the O(n log n) lower bound that applies to comparison-based sorts. For n integers with at most k digits, time complexity is O(nk), which beats merge sort when k is small relative to log₂ n. Used in database sort operations, network packet classification, and suffix array construction.
