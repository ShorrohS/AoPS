Type A — Chapter Hero FIG 5.1-A Stack vs Heap — Two Memory Regions, Two Lifetimes
C memory model: stack vs heap. Local variables like int x = 42 are allocated automatically on the stack at function entry and freed automatically on return — the compiler manages this. Heap allocations via malloc() give the programmer explicit control: the memory persists until free() is called. The pointer p (the variable holding the address) lives on the stack; the pointed-to data lives on the heap. Forgetting to call free() is a memory leak. Calling free() twice, or dereferencing p after free(), is undefined behaviour. These are the most common class of C bugs and the primary motivation for memory-safe languages like Rust.
Type C — Concept Diagram FIG 5.1-B Pointers in Memory — Address, Dereference, Pointer Arithmetic
Pointer mechanics in C. An integer array arr[4] occupies four contiguous 4-byte slots starting at address 0x1000. The pointer p stores the address 0x1000 — p itself is a variable on the stack holding a number. The dereference operator *p reads the value at that address (10). Pointer arithmetic p+1 does not add 1 to the address — it adds sizeof(int) = 4 bytes, advancing to the next array element at 0x1004. This is why p[i] is exactly equivalent to *(p + i) in C — array subscripting is defined in terms of pointer arithmetic. This direct correspondence between arrays, pointers, and memory addresses is C's greatest power and greatest source of bugs.
