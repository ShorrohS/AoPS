Type A — Chapter Hero FIG 5.5-A Bubble Sort — Step-by-Step Trace on [5, 3, 8, 1, 9, 2]
Bubble sort pass 1 on [5, 3, 8, 1, 9, 2]. The algorithm compares adjacent elements and swaps them if out of order. After pass 1, the largest element (9) has "bubbled" to its final position. After pass 2, the second-largest reaches its place, and so on. O(n²) total comparisons: n(n-1)/2. For n=1000, that is about 500,000 comparisons. Bubble sort is studied for its algorithmic clarity, not its practical performance — it motivates the search for O(n log n) algorithms that can sort a million elements in ~20 million operations instead of ~500 billion.
Type C — Process Diagram FIG 5.5-B Merge Sort — Divide, Conquer, Combine
Merge sort on [5, 3, 8, 1]. The divide phase recursively splits the array in half until single-element arrays are reached (trivially sorted). The conquer phase merges adjacent sorted pairs into larger sorted arrays. The merge step compares the front elements of two sorted arrays and takes the smaller — O(n) work per level. With log n recursive levels, total work is O(n log n) — guaranteed regardless of input order. Merge sort is stable (preserves equal elements' order) and optimal for comparison-based sorting by the lower-bound proof.
Type D — Reference Table FIG 5.5-C Sorting Algorithm Comparison — Complexity, Stability, Space
Sorting algorithm comparison across complexity, space, and stability properties. The O(n log n) lower bound applies to comparison-based sorting — no algorithm that only compares elements can sort faster in the general case. Practical choice: Quicksort for general purpose (fastest in cache, O(n log n) average), Merge Sort when stability is required, Heap Sort when guaranteed worst-case O(n log n) with O(1) space is needed, Insertion Sort for small or nearly-sorted arrays, Radix Sort when keys are integers and the digit count k is small. Python's Timsort is a hybrid merge-insertion sort optimised for real-world data patterns.
