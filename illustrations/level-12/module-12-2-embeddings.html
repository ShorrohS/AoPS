Module 12.2 — Embeddings and Vector Databases
3 figures · Word Embedding Space · Cosine Similarity · Vector Database Architecture
Type A — Chapter Hero FIG 12.2-A Word Embedding Space — Semantic Relationships Encoded as Geometry
Word embeddings map tokens to dense vectors in a high-dimensional space where geometric relationships encode semantic meaning. Words with similar meanings cluster together — "cat", "dog", "tiger" form an animals cluster. The remarkable property discovered with word2vec (Mikolov 2013): vector arithmetic preserves semantic relationships — king − man + woman ≈ queen. This works because the "royalty" and "gender" concepts are encoded as consistent directions in embedding space. Modern contextual embeddings (BERT, GPT) produce different vectors for the same word in different contexts: "bank" near "river" gets a different vector than "bank" near "deposit". These contextual vectors form the basis of semantic search, RAG systems, and recommendation engines.
Type B — Concept Diagram FIG 12.2-B Cosine Similarity — Angular Distance as Semantic Similarity
Cosine similarity measures the angle between two vectors, ignoring magnitude. cos(θ) = (a · b) / (|a| |b|). Range: +1 (same direction, identical meaning), 0 (perpendicular, unrelated), -1 (opposite direction, antonym or unrelated). Cosine similarity is preferred over Euclidean distance for embeddings because magnitude is often irrelevant — a long document and a short document about the same topic should be considered similar even though their embedding vectors have different magnitudes. Near-duplicates like "cat"/"feline" score above 0.9. Related concepts like "cat"/"dog" score 0.6–0.8. Unrelated concepts score near 0. Vector databases index millions of embeddings and find the top-K nearest vectors by cosine similarity in milliseconds using approximate nearest neighbour (ANN) algorithms like HNSW.
Type D — Architecture Diagram FIG 12.2-C Vector Database Architecture — HNSW Index for Approximate Nearest Neighbour
Vector databases store high-dimensional embeddings and support fast nearest-neighbour search. The HNSW (Hierarchical Navigable Small World) index organises vectors in a multi-layer graph: the top layers are sparse, providing "highway" connections for long-distance jumps; the bottom layer contains all vectors with local connections. Search starts at the top layer and greedily navigates toward the query vector, descending to denser layers as it converges. This achieves O(log n) approximate nearest neighbour search — finding the top-K most similar vectors among 1 million in under 10ms with ~99% recall. Vector databases (Pinecone, Qdrant, Weaviate, pgvector) are the retrieval backbone of RAG systems, semantic search engines, and recommendation systems.
