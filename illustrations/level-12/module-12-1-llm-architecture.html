Type A — Chapter Hero FIG 12.1-A Tokenisation — Text to Token IDs via Byte Pair Encoding
Tokenisation converts raw text into integer sequences that the model processes. Byte Pair Encoding (BPE) starts with a character-level vocabulary and iteratively merges the most frequent adjacent pair of tokens until a target vocabulary size is reached (~50,000 for GPT-2). Common words like "the" map to a single token. Rare words and neologisms are split into subword pieces ("transform" + "er"). This balances vocabulary size against sequence length — pure character tokenisation produces sequences 4-10× longer, dramatically increasing attention computation. Token IDs are the actual inputs to the model, which first looks them up in an embedding table to get continuous vector representations.
Type B — Architecture Diagram FIG 12.1-B Transformer Decoder Block — Attention, FFN, Residuals, Layer Norm
Transformer decoder block — the architectural unit stacked N times in GPT-style language models. Pre-layer normalisation stabilises training. Causal self-attention (masked so each token can only attend to previous tokens) captures context. The feed-forward network (two linear layers with GELU activation, expanding to 4× the model dimension internally) applies position-wise transformations. Residual connections ("skip connections") allow gradients to flow directly through the network without vanishing, enabling stacks of 96+ blocks. The final linear layer projects to vocabulary size (~50,000), and softmax converts logits to a probability distribution over the next token. Training: predict the next token at every position simultaneously (teacher forcing), minimise cross-entropy loss over the entire training corpus.
Type C — Process Diagram FIG 12.1-C Self-Attention Mechanism — Q, K, V Matrices and Attention Scores
Self-attention is the core operation of the Transformer. Each input token is projected into three vectors: Query (what information am I looking for?), Key (what information do I contain?), and Value (what information should I provide?). Attention scores are computed as dot products of queries with all keys, scaled by √dₖ to prevent extremely small gradients, then normalised with softmax to form attention weights. The output is a weighted sum of value vectors — each token's output is a mixture of all other tokens' values, weighted by how relevant those tokens are. Causal masking sets attention weights to zero for future tokens, enabling autoregressive generation. Multi-head attention runs H parallel attention operations with different projections, allowing the model to capture different types of relationships simultaneously.
