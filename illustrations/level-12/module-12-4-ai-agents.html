Type A — Chapter Hero FIG 12.4-A AI Agent Architecture — Perception, Memory, Planning, Action Loop
An AI agent uses an LLM as its reasoning core, augmented with tools (external capabilities) and memory. The agent loop: perceive the environment (user request, sensor data, prior action results), retrieve relevant memories and knowledge, reason with the LLM about what to do next, act by calling tools (web search, code execution, APIs, file I/O), observe the results, and repeat until the task is complete. Short-term memory is the LLM's context window — limited in size. Long-term memory is a vector database or external storage, accessed via retrieval. This architecture allows an LLM (which is fundamentally a text completion model) to autonomously complete multi-step tasks that require planning, tool use, and adapting to intermediate results.
Type C — Process Diagram FIG 12.4-B ReAct Pattern — Interleaved Reasoning and Action
ReAct (Reason + Act) is the dominant agent prompting pattern. The LLM interleaves Thought (internal chain-of-thought reasoning about what to do), Action (a structured tool call), and Observation (the tool's result). This loop continues until the agent has enough information to produce a final answer. ReAct prevents hallucination on factual questions by requiring the agent to ground its answer in tool-retrieved evidence rather than parametric memory. The structured Thought-Action-Observation format also makes agent behaviour transparent and debuggable — the reasoning trace is human-readable. ReAct is the foundation of LangChain, AutoGPT, and virtually all production AI agent frameworks.
Type D — Architecture Diagram FIG 12.4-C Multi-Agent System — Orchestrator Delegates to Specialist Agents
Multi-agent systems decompose complex tasks across specialised agents. An orchestrator LLM receives a high-level task, breaks it into subtasks, and delegates each to a specialist: a research agent with web search tools, a code agent with execution capabilities, a critic agent for review and fact-checking, and API agents for external integrations. Specialist agents complete their subtasks and return results; the orchestrator synthesises them into a final response. This architecture mirrors human team organisation — specialists are better and faster at their narrow domains, and coordination overhead is worth it for complex tasks. Challenges: latency (agents run sequentially or in parallel), error propagation, and ensuring the orchestrator correctly decomposes and routes tasks.
