Type A — Chapter Hero FIG 12.3-A RAG Pipeline — Document Chunking, Embedding, Retrieval, Generation
Retrieval-Augmented Generation (RAG) grounds LLM responses in a document corpus. Offline: documents are chunked (typically 256–512 tokens with 50-token overlap between chunks), embedded into vector representations, and stored in a vector database. Online: the user's question is embedded with the same model, the top-K most similar chunks are retrieved by vector similarity, and these chunks are injected into the LLM's prompt as context. The LLM generates an answer conditioned on both the question and the retrieved context — dramatically reducing hallucination and enabling citation of sources. RAG solves LLMs' two biggest limitations: knowledge cutoff (inject current documents at inference time) and hallucination on specific facts (ground the model in retrieved evidence rather than parametric memory).
Type E — Comparison FIG 12.3-B Semantic Search vs Keyword Search — Understanding vs Matching
Semantic search vs keyword search on the same query. BM25 (keyword search) scores documents by exact word frequency — it finds documents containing "code" and "faster" but misses "performance optimisation", "profiling", and "algorithmic complexity" — all directly relevant, zero keyword overlap. Vector semantic search embeds both the query and documents into the same semantic space, finding documents by meaning rather than word match. The query "how do I make my code faster" and the document "reducing algorithmic complexity" share no words but are semantically close — the embedding model learned that these concepts are related from training data. In practice, hybrid search (BM25 + vector search, scores combined) outperforms either alone — BM25 excels at precise keyword matches (product names, IDs), semantic search handles meaning and synonymy.
Type E — Comparison FIG 12.3-C RAG vs Fine-tuning vs Prompting — When to Use Each Approach
Three strategies for incorporating domain knowledge into LLM responses. Prompting (in-context learning) injects knowledge directly into the prompt — free to update but limited by context window length and per-call cost. RAG retrieves relevant chunks at runtime from an external knowledge base — knowledge can be updated by changing the indexed documents, the LLM weights never change. Fine-tuning trains the model weights on domain data, baking knowledge into parameters — powerful for behavioural changes (tone, format, domain vocabulary) but expensive, requires retraining when knowledge updates, and can cause "forgetting" of general capabilities. The practical heuristic: start with RAG (much cheaper and updatable), add fine-tuning only if RAG cannot achieve the required behaviour or latency.
