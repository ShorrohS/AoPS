﻿# Module 12.1 — Large Language Models: Architecture and Training

The Problem

In 2017, a team at Google published "Attention Is All You Need." The transformer architecture they described — without convolutions or recurrence — became the foundation of GPT, BERT, Claude, Gemini, LLaMA, and virtually every large language model in existence.

How does a system trained to predict the next word in a document learn to write code, translate languages, answer questions, and reason about complex problems?

Understanding the transformer architecture — from attention mechanisms to the training process — is the prerequisite for working with any modern AI system at a technical level.

The Story

The Road to Transformers

Recurrent Neural Networks (RNNs) and their variants — LSTMs (Hochreiter & Schmidhuber, 1997) and GRUs — dominated sequence modelling from the 2000s. They processed tokens one at a time, maintaining a hidden state. The problem: long-range dependencies were hard to learn (vanishing gradients even with LSTM), and sequential processing prevented parallelisation.

Sequence-to-sequence models (Sutskever, Vinyals, Le, 2014) added an encoder-decoder structure with attention — the decoder could "attend" to different parts of the encoder's output. This was the breakthrough for machine translation.

"Attention Is All You Need" (Vaswani et al., Google, 2017) eliminated recurrence entirely. Pure attention. Every token attends to every other token in the sequence simultaneously. Training is fully parallelisable. The result: dramatically larger models could be trained.

GPT-1 (OpenAI, 2018): the first demonstration that large-scale pretraining on text + fine-tuning worked for many tasks. 117 million parameters. GPT-2 (2019): 1.5B parameters. GPT-3 (2020): 175B parameters, few-shot learning without fine-tuning. GPT-4 (2023): architecture undisclosed, dramatically better. The scale at which capabilities emerged was surprising even to the researchers.

The Concept

Tokenisation

Before processing text, the model converts it to tokens — integer IDs from a fixed vocabulary.

BPE (Byte Pair Encoding): the dominant tokenisation scheme for LLMs. Start with individual bytes, iteratively merge the most frequent adjacent pair:

"the cat sat" → ["the", " cat", " sat"]
                → [464, 3797, 4992]  (GPT-4 token IDs)

GPT-4 uses ~100,000 tokens. Common words are single tokens ("the" → 1 token). Uncommon or non-English words may split into multiple tokens ("Königsberg" → ["K", "ön", "igs", "berg"] → 4 tokens).

Why it matters: token count affects both cost and context length. A 4,096-token context window is roughly 3,000 words of English.

Self-Attention — The Core Mechanism

Self-attention allows every token to "look at" every other token and incorporate relevant context.

For each token, compute three vectors via learned linear projections:

  • Query (Q): "what am I looking for?"
  • Key (K): "what do I contain?"
  • Value (V): "what do I provide if attended to?"
import numpy as np

def self_attention(X, W_Q, W_K, W_V):
    # X shape: (seq_len, d_model)
    Q = X @ W_Q    # (seq_len, d_k)
    K = X @ W_K    # (seq_len, d_k)
    V = X @ W_V    # (seq_len, d_v)

    # Attention scores: how much each token attends to each other
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)    # (seq_len, seq_len)

    # For causal (decoder) models: mask future tokens
    # scores[i, j] = -inf if j > i  (can't attend to future)

    # Softmax over keys for each query
    weights = softmax(scores, axis=-1)    # (seq_len, seq_len)

    # Weighted sum of values
    output = weights @ V    # (seq_len, d_v)
    return output

Multi-head attention: run h parallel attention heads with different W_Q, W_K, W_V projections. Each head can attend to different aspects of the input. Concatenate and project:

def multi_head_attention(X, num_heads, W_Q, W_K, W_V, W_O):
    # Split into heads, apply attention, concatenate
    head_dim = d_model // num_heads
    heads = []
    for h in range(num_heads):
        # Each head has its own projections
        out = self_attention(X, W_Q[h], W_K[h], W_V[h])
        heads.append(out)
    concat = np.concatenate(heads, axis=-1)   # (seq_len, d_model)
    return concat @ W_O                        # (seq_len, d_model)

Positional Encoding

Self-attention is order-invariant (shuffling tokens gives the same attention scores). Positional encodings inject position information:

Sinusoidal positional encoding (original Transformer):

def positional_encoding(seq_len, d_model):
    PE = np.zeros((seq_len, d_model))
    for pos in range(seq_len):
        for i in range(0, d_model, 2):
            PE[pos, i]   = np.sin(pos / 10000**(i / d_model))
            PE[pos, i+1] = np.cos(pos / 10000**(i / d_model))
    return PE

Modern LLMs (GPT-NeoX, LLaMA) use RoPE (Rotary Positional Embedding) — relative position encoding that generalises better to sequences longer than seen during training.

Pretraining: Next-Token Prediction

LLMs are trained on the causal language modelling objective: given tokens 1..t, predict token t+1. For a sequence of N tokens, one forward pass generates N training examples (teacher forcing):

# Input:  [The, cat, sat, on]
# Target: [cat, sat, on, the]   (each token predicts the next)

# Cross-entropy loss over vocabulary for each position
loss = -sum(log P(token_t+1 | tokens_1..t) for t in 1..N-1) / (N-1)

This simple objective — predict the next token — when applied to hundreds of billions of tokens from the web, books, and code, produces a model that learns to compress and generalise the statistical structure of human language and knowledge.

Why does next-token prediction produce "understanding"? The hypothesis: to predict the next token well, a model must learn everything knowable about the context — facts, reasoning patterns, coding conventions, stylistic norms. The task is simple; the knowledge required to do it well is enormous.

Inference: Autoregressive Generation

At inference time, the model generates tokens one at a time:

def generate(model, prompt_tokens, max_new_tokens, temperature=1.0):
    tokens = list(prompt_tokens)
    for _ in range(max_new_tokens):
        logits = model.forward(tokens)        # (vocab_size,) for last position
        logits /= temperature                  # temperature scales confidence
        probs = softmax(logits)
        next_token = np.random.choice(len(probs), p=probs)   # sample
        tokens.append(next_token)
        if next_token == EOS_TOKEN: break
    return tokens[len(prompt_tokens):]

Temperature: lower → more deterministic (greedy), higher → more random. Top-k sampling: only consider the k most likely tokens. Top-p (nucleus) sampling: only consider tokens whose cumulative probability ≥ p.

The KV cache stores key/value matrices for previously generated tokens, so each new token only requires one new row of attention computation rather than recomputing the entire sequence.

Going Deeper

Scaling laws: Kaplan et al. (OpenAI, 2020) showed that language model loss decreases as a power law with: number of parameters (N), training tokens (D), and compute (C=6ND). These scaling laws predicted the performance of GPT-3 and GPT-4 before they were trained. They also suggested an "optimal" allocation of compute between model size and data size.

Emergent capabilities: behaviours that appear only above certain model scales — arithmetic, chain-of-thought reasoning, code generation, in-context learning. Smaller models simply cannot do these things; larger models do them without explicit training on those tasks. The emergence appears sudden relative to scale. Understanding why capabilities emerge at scale is one of the most important open questions in AI research.

▸ Part A.1–4 — attention computation
import numpy as np

def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)         # (4,4)

    if mask is not None:
        scores = np.where(mask, scores, -1e9)  # -1e9 approximates -inf

    # Softmax (numerically stable)
    scores_exp = np.exp(scores - scores.max(axis=-1, keepdims=True))
    weights = scores_exp / scores_exp.sum(axis=-1, keepdims=True)

    return weights @ V   # (4,4)

# Causal mask (lower triangular)
mask = np.tril(np.ones((4,4), dtype=bool))
output = scaled_dot_product_attention(Q, K, V, mask)

Output shape: (4, 4). Each row i is the attention-weighted combination of V rows, where token i can only attend to tokens 0..i (causal).

▸ Part B.8 — KV cache size

After 30 tokens (10 prompt + 20 generated):

  • Per layer, K shape: (30, 32, 128) = 122,880 values
  • Per layer, V shape: same
  • Both K and V: 245,760 values per layer
  • 32 layers: 32 × 245,760 = 7,864,320 values
  • float16 (2 bytes): 15,728,640 bytes ≈ 15 MB for 30 tokens

For 1M tokens: 1,000,000/30 × 15 MB ≈ 500 GB. This is why long-context models require significant GPU memory.

﻿# Module 12.2 — Embeddings and Vector Databases

The Problem

Computers understand numbers. Text, images, audio, code — all must be converted to numbers before a computer can process them.

But a simple conversion (character codes, pixel values) misses semantic structure. "cat" and "feline" are the same concept — but their character codes share nothing. "cat" and "can" differ by one character — but they are completely different concepts.

Embeddings solve this: map objects (words, sentences, images, code) to vectors such that semantically similar objects are geometrically close. Vector databases provide efficient similarity search over millions of these vectors.

The Story

Word2Vec — Meaning from Context

Word2Vec (Mikolov et al., Google, 2013) demonstrated that word meaning could be captured by training a shallow neural network to predict words from their context in a large text corpus ("you shall know a word by the company it keeps" — J.R. Firth, 1957).

The emergent property was remarkable: the resulting vectors supported arithmetic: king - man + woman ≈ queen. Geographic capitals, verb tenses, comparative adjectives — the structure of meaning was encoded in geometric relationships between vectors.

GloVe (Stanford, 2014) and FastText (Facebook, 2016) improved on Word2Vec. But word-level embeddings had a fundamental limitation: "bank" had one vector regardless of whether it meant a financial institution or a river bank.

BERT (Google, 2018) introduced contextual embeddings — each token's embedding depends on all surrounding tokens. "Bank" has a different vector in "river bank" and "bank transfer." These contextual embeddings, derived from transformers (Module 12.1), are now the foundation of all embedding models.

The Concept

What Is an Embedding?

An embedding is a function that maps an object to a dense vector in ℝᵈ where d is typically 128–4096 dimensions.

The critical property: semantic similarity ≈ geometric proximity. Objects with similar meaning have vectors that are close (high cosine similarity).

from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer('all-MiniLM-L6-v2')  # 384 dimensions

# Text embeddings
e1 = model.encode("The quick brown fox")
e2 = model.encode("A fast auburn canine")    # similar meaning
e3 = model.encode("The stock market fell")   # different topic

def cosine_sim(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

print(cosine_sim(e1, e2))   # ≈ 0.78 (similar)
print(cosine_sim(e1, e3))   # ≈ 0.12 (different)

Types of Embeddings

Word embeddings: map individual words to vectors. Word2Vec, GloVe, FastText. Useful for token-level tasks.

Sentence/document embeddings: map entire sentences or paragraphs to a single vector. Sentence-BERT, OpenAI Ada, Cohere Embed. Used for semantic search, classification, clustering.

Multimodal embeddings: map different modalities (text and images) to the same vector space. CLIP (OpenAI, 2021) — trained on 400M image-text pairs, can compare images and text directly. Enables: image search with text queries, text-to-image generation guidance.

Code embeddings: map code snippets to vectors capturing functional semantics. OpenAI code-embedding, CodeBERT. Enables: code search ("find all functions that sort a list"), similar code detection, documentation search.

Vector Similarity Search

Given a query vector q and a database of n vectors {v₁, ..., vₙ}, find the k most similar vectors.

Brute force: compute cosine similarity with all n vectors. O(n×d) per query. Exact but slow for large n.

Approximate Nearest Neighbour (ANN): trade small accuracy loss for massive speed-up. Used in all production vector databases.

FAISS (Facebook AI Similarity Search):

import faiss
import numpy as np

# Build an index
d = 384            # embedding dimension
n = 1_000_000      # number of vectors

embeddings = np.random.randn(n, d).astype('float32')
embeddings /= np.linalg.norm(embeddings, axis=1, keepdims=True)   # normalise

# IVF (Inverted File) index: cluster vectors, search only relevant clusters
nlist = 100        # number of clusters
quantiser = faiss.IndexFlatIP(d)   # exact search within cluster
index = faiss.IndexIVFFlat(quantiser, d, nlist, faiss.METRIC_INNER_PRODUCT)
index.train(embeddings)            # cluster the data
index.add(embeddings)              # add all vectors

# Search
query = np.random.randn(1, d).astype('float32')
query /= np.linalg.norm(query)

index.nprobe = 10                  # search 10 clusters (speed/accuracy tradeoff)
distances, indices = index.search(query, k=5)
# Returns indices of 5 nearest neighbours in ~milliseconds

HNSW (Hierarchical Navigable Small World): a graph-based ANN algorithm. Vectors are nodes; edges connect nearby vectors in a hierarchy of layers. Search navigates the graph greedily from the top layer. Very fast (~1ms for millions of vectors), good accuracy. Used by Weaviate, Qdrant.

Embedding Fine-Tuning

Pre-trained embedding models may not capture domain-specific meaning. Fine-tuning on domain data improves retrieval quality:

Contrastive learning: train the model so similar pairs (query, relevant document) have high similarity and dissimilar pairs have low similarity:

Loss = -log(exp(sim(q, d+) / τ) / Σⱼ exp(sim(q, dⱼ) / τ))

where d+ is the positive (relevant) document, dⱼ are all documents in the batch, τ is temperature.

INSTRUCTOR and E5 are instruction-tuned embedding models that can be customised via natural language: INSTRUCTION: Represent the technical documentation for retrieval. INPUT: {document}.

Going Deeper

Matryoshka Representation Learning (MRL): train embedding models so that the first d dimensions of a 1536-d embedding are themselves a good d-dimensional embedding. This allows using shorter embeddings (faster, cheaper) for coarse search and longer embeddings for re-ranking. OpenAI's text-embedding-3 models support Matryoshka embeddings.

Late interaction models (ColBERT): instead of compressing a document to one vector, keep all token-level vectors. At query time, compute the maximum similarity between each query token and each document token (MaxSim). Much more accurate than single-vector retrieval, but requires more storage and more compute.

import numpy as np

def cosine_similarity(a, b):
    a, b = np.array(a), np.array(b)
    dot = np.dot(a, b)
    norm_a = np.linalg.norm(a)
    norm_b = np.linalg.norm(b)
    if norm_a == 0 or norm_b == 0: return 0.0
    return dot / (norm_a * norm_b)

﻿# Module 12.3 — Retrieval-Augmented Generation

The Problem

A large language model knows everything in its training data — up to its cutoff date. But it cannot:

  • Access information created after training
  • Look up specific private documents you have
  • Cite its sources reliably
  • Know about your company's internal policies

RAG (Retrieval-Augmented Generation) solves this by combining a retrieval system with a language model: instead of relying entirely on parametric memory (weights), the model retrieves relevant context at query time and uses it to answer.

The Story

From Parametric to Non-Parametric Knowledge

Early neural networks had no external memory — all knowledge was encoded in parameters. Neural Turing Machines (Graves et al., Google DeepMind, 2014) added an external memory with differentiable read/write heads — inspired by Turing's theoretical computing model.

RAG (Lewis et al., Facebook AI Research, 2020) applied a simpler but practical approach: use a non-parametric retrieval system (dense passage retrieval with FAISS) combined with a generative model. The model sees retrieved documents concatenated to the question. It was the first major demonstration that retrieval could dramatically improve factuality.

With the commercial success of ChatGPT (2022), RAG became the dominant architecture for enterprise AI applications: internal knowledge bases, customer support chatbots, code assistance with private repositories, legal document search.

The Concept

RAG System Architecture

User query
    ↓
[Query Encoder]          ← embedding model
    ↓

    ↓

    ↓

    ↓

    ↓

    ↓

Building a RAG System from Scratch

Step 1: Indexing — run once when documents change

import faiss
from sentence_transformers import SentenceTransformer

def build_index(documents):
    model = SentenceTransformer('all-MiniLM-L6-v2')
    embeddings = model.encode(documents, convert_to_numpy=True)
    embeddings = embeddings / np.linalg.norm(embeddings, axis=1, keepdims=True)  # normalise

    # FAISS index for cosine similarity (using inner product on normalised vectors)
    dim = embeddings.shape[1]
    index = faiss.IndexFlatIP(dim)
    index.add(embeddings)
    return index, embeddings

documents = [
    "Python was created by Guido van Rossum in 1991.",
    "The GIL in CPython prevents true parallelism for CPU-bound threads.",
    "NumPy provides efficient array operations built on LAPACK/BLAS.",
    # ... thousands more documents
]

Step 2: Retrieval — run for each query

def retrieve(query, index, documents, model, k=3):
    query_embedding = model.encode([query], convert_to_numpy=True)
    query_embedding /= np.linalg.norm(query_embedding, axis=1, keepdims=True)

    # Find k nearest neighbours
    scores, indices = index.search(query_embedding, k)

    results = []
    for score, idx in zip(scores[0], indices[0]):
        results.append({
            'document': documents[idx],
            'score': float(score),
        })
    return results

Chunking Strategy

Documents must be split into chunks before embedding. Chunking strategy dramatically affects retrieval quality:

Fixed-size chunks: split every N characters (simple, fast, breaks mid-sentence).

Sentence/paragraph chunks: split on sentence boundaries (better coherence, variable size).

Sliding window: overlapping chunks so context boundaries don't cause misses:

def chunk_text(text, chunk_size=500, overlap=50):
    words = text.split()
    chunks = []
    for i in range(0, len(words), chunk_size - overlap):
        chunk = ' '.join(words[i:i + chunk_size])
        chunks.append(chunk)
        if i + chunk_size >= len(words): break
    return chunks

Semantic chunking: split when topic changes (detected by embedding similarity drop). More expensive but better for heterogeneous documents.

RAG Evaluation

How do you measure whether a RAG system is working?

Retrieval metrics:

  • Context recall: what fraction of the answer's relevant information was retrieved?
  • Context precision: what fraction of retrieved documents are relevant?

Generation metrics:

  • Faithfulness: does the answer only use information from the retrieved context? (measures hallucination)
  • Answer relevance: does the answer actually address the question?

Ragas (open-source RAG evaluation framework) automates these measurements using an LLM as a judge.

Going Deeper

Hybrid retrieval: combine dense vector search (semantic similarity) with BM25 sparse retrieval (keyword matching). Reciprocal Rank Fusion (RRF) merges the two ranked lists. Hybrid retrieval consistently outperforms pure dense or sparse retrieval on diverse queries — especially for technical terms and proper nouns that dense models may not embed well.

GraphRAG (Microsoft, 2024): instead of retrieving individual document chunks, build a knowledge graph from the corpus. Queries traverse the graph to find semantically related entities and relationships, then summarise the subgraph. Dramatically better for questions that require synthesising information across many documents rather than finding a single relevant passage.

﻿# Module 12.4 — AI Agents: Planning, Tool Use, and Memory

The Problem

A large language model can answer a question. But it cannot: browse the web to find current information, write code and run it to check if it works, send an email, query a database, or interact with an API.

An AI agent extends the LLM with the ability to take actions: use tools, execute code, interact with external systems, and — most importantly — plan a sequence of actions to achieve a goal.

This is the difference between an assistant that tells you how to do something and one that actually does it.

The Story

From Chatbots to Agents

The ELIZA chatbot (Weizenbaum, MIT, 1966) simulated a therapist through simple pattern matching. Users ascribed understanding to it despite its mechanical simplicity — the first demonstration of how humans project intelligence onto text.

ReAct (Reason + Act, Yao et al., 2022) was a key paper showing that LLMs could interleave reasoning (thinking through a problem) with action (using tools to gather information). The model writes its "thoughts" in text, then calls a tool, observes the result, thinks further. This simple pattern enabled solving problems that pure generation couldn't.

AutoGPT (2023) was an early attempt at autonomous agents — GPT-4 calling itself recursively, maintaining a task list, browsing the web, and writing files. It attracted enormous attention but also demonstrated the failure modes: lack of planning, context window limits, cascading errors.

LangChain, LlamaIndex, Claude's tool use, OpenAI Function Calling — all subsequent frameworks for building agents have converged on the same core pattern: give the LLM a set of tools, let it decide which to call and when.

The Concept

The ReAct Loop

User Goal
    ↓
[Thought]: Reason about what to do next
    ↓
[Action]: Call a tool (search, code execution, API call)
    ↓
[Observation]: Receive tool output
    ↓
(repeat Thought → Action → Observation until goal achieved)
    ↓
[Final Answer]

Example trace:

Goal: What is the current Python version and what was the main change in that release?

Thought: I need to find the current Python version. I'll search for it.
Action: web_search("current Python version 2026")
Observation: Python 3.13 was released in October 2024. Python 3.14 is in development.

Thought: I have the version. Now I need to find the main changes in Python 3.13.
Action: web_search("Python 3.13 major changes features")
Observation: Python 3.13 introduced experimental free-threaded mode (no GIL), improved error messages, and a new REPL.

Final Answer: The current stable Python version is 3.13. Its major changes include experimental GIL-free threading, improved error messages, and a redesigned interactive interpreter.

def run_agent(goal, tools, tool_executors, max_steps=10):

    for step in range(max_steps):
        response = openai.chat.completions.create(
            model="gpt-4o",

        if not msg.tool_calls:
            return msg.content

        # Execute each tool call
        for tool_call in msg.tool_calls:
            name = tool_call.function.name
            args = json.loads(tool_call.function.arguments)
            result = tool_executors[name](**args)

            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": str(result)
            })

    return "Max steps reached"

Memory Types

An agent that forgets context is limited. Different tasks require different memory:

In-context memory: everything in the current prompt. Fast, exact, but limited to context window (4K–200K tokens depending on model).

Episodic memory: store past conversations and retrieve relevant ones via embedding similarity:

def remember(agent, interaction):
    embedding = embed(interaction['summary'])
    memory_db.upsert(embedding, interaction)

def recall(agent, query, k=3):
    query_emb = embed(query)
    return memory_db.search(query_emb, k)

Semantic memory: distilled facts extracted from experience. "User prefers Python over JavaScript." "This codebase uses pytest for testing." Stored and retrieved as structured facts.

Procedural memory: how to do specific tasks. Often stored as few-shot examples retrieved from a library.

Planning

For complex multi-step goals, ad-hoc tool use is insufficient. Planning approaches:

Chain of Thought (CoT): instruct the model to reason step by step before acting. Dramatically improves performance on complex tasks without any additional architecture.

Tree of Thought (ToT): generate multiple reasoning paths, evaluate each, select the most promising. Better for tasks where the correct approach is not obvious.

Plan-and-Execute: generate a complete plan upfront, then execute each step:

def plan_then_execute(goal, llm, executor):
    # Step 1: generate a plan
    plan_prompt = f"Create a step-by-step plan to: {goal}\nSteps:"
    plan = llm(plan_prompt)

    # Step 2: execute each step
    results = []
    for step in parse_plan(plan):
        result = executor.run(step)
        results.append(result)

    # Step 3: synthesise results
    return llm(f"Based on these results: {results}\nAnswer: {goal}")

Reflexion (Shinn et al., 2023): after failure, the agent reflects on what went wrong and stores a verbal critique in memory. On retry, the critique guides better behaviour. Significantly improves agent performance on tasks requiring exploration.

Going Deeper

Agent safety and sandboxing: an agent that can execute code and call APIs can cause real damage — delete files, send emails, make purchases. Production agent systems need: sandboxed execution environments (Docker containers, WASM), minimal permissions (only what the task requires), human confirmation for high-stakes actions, and detailed audit logs. The problem of building agents that are powerful enough to be useful but constrained enough to be safe is an active area of both engineering and research.

Context window management: a long-running agent accumulates context. At some point the context window is full. Strategies: summarise older exchanges and replace them with the summary, use retrieval over conversation history, implement a sliding window. Each strategy loses some information — the right approach depends on what the task requires.

﻿# Module 12.5 — Ethics and Safety in AI Systems

The Problem

A hiring algorithm trained on historical data learns to discriminate. A content recommendation system optimises engagement — and radicalises users. A self-driving car must decide who to harm in an unavoidable crash. A large language model confidently states false information.

These are not hypothetical future problems. They are happening now, in systems deployed at scale.

Building AI systems responsibly requires understanding not just the technical mechanisms but the ethical frameworks, failure modes, and safety techniques that prevent harm.

The Story

From Science Fiction to Policy

The ethics of artificial intelligence has been discussed since the technology was theoretical. Isaac Asimov's Three Laws of Robotics (1942) were the first popular framing — and Asimov's stories systematically showed why rule-based ethics fails in complex situations.

Real concerns emerged as AI systems moved from research to deployment:

  • 2014: Microsoft's Tay chatbot learned to generate hate speech within 24 hours of deployment
  • 2016: ProPublica reported that COMPAS (a recidivism prediction system) showed racial bias in US courts
  • 2019: Amazon scrapped an AI recruiting tool that discriminated against women (trained on historical hiring data that was male-dominated)
  • 2022: ChatGPT demonstrated that large language models could produce fluent, confident, incorrect text — "hallucination" — at scale
  • 2023–2024: Regulatory responses — EU AI Act, US Executive Order on AI — attempted to create frameworks for accountability

The technical AI safety field grew from concerns about existential risk. Nick Bostrom's Superintelligence (2014) and work at organisations like MIRI (Machine Intelligence Research Institute) and later Anthropic focused on alignment: how do you ensure an AI system pursues the goals its creators intended, not some proxy that diverges catastrophically?

The Concept

Bias and Fairness

What is bias in ML? A model trained on biased data learns biased patterns.

# Simplified example
# Historical data: women hired at lower rates (due to past discrimination)
# Model trained on this data: predicts women as lower probability hires
# Outcome: perpetuates and entrenches the historical bias

Sources of bias:

  • Historical bias: data reflects past discrimination
  • Representation bias: certain groups are underrepresented in training data
  • Measurement bias: the variable being predicted is a proxy for something else
  • Feedback loops: biased predictions → biased outcomes → biased future training data

Fairness metrics (often incompatible with each other):

  • Demographic parity: equal positive prediction rates across groups
  • Equal opportunity: equal true positive rates across groups
  • Predictive parity: equal precision across groups
  • Individual fairness: similar individuals treated similarly

Impossibility results: it is mathematically impossible to satisfy all fairness criteria simultaneously when base rates differ between groups. Any choice of fairness definition encodes a value judgment — there is no purely technical solution to what is fundamentally a societal question.

Explainability and Interpretability

The black box problem: deep neural networks make decisions through millions of learned parameters. Even the system's creators cannot fully explain why it made a specific decision.

Why it matters: in high-stakes domains (medical diagnosis, loan decisions, criminal justice), decision subjects have a right to an explanation. The EU GDPR includes a "right to explanation" for automated decisions.

Techniques:

  • LIME (Local Interpretable Model-Agnostic Explanations): approximate the model locally with a simpler interpretable model
  • SHAP (SHapley Additive exPlanations): use Shapley values (from game theory) to attribute each feature's contribution to a prediction
  • Attention visualisation: in transformer models, attention weights show which input tokens influenced the output
  • Gradient-based saliency: compute the gradient of the output with respect to inputs to identify which inputs most affected the decision
import shap

explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X_test)
shap.summary_plot(shap_values, X_test, feature_names=feature_names)

Hallucination and Truthfulness

Hallucination: a language model confidently states false information. This is not a bug in the traditional sense — it is an emergent property of how LLMs work:

  • LLMs are trained to predict likely next tokens, not to retrieve facts from a verified database
  • Fluent, confident-sounding text and accurate text are statistically correlated but not identical
  • The model has no internal "truth check" — it cannot distinguish what it knows from what it is confabulating

Mitigation techniques:

  • Retrieval-Augmented Generation (RAG): ground LLM responses in retrieved documents (Module 12.3)
  • Calibration: train models to express uncertainty when appropriate
  • Constitutional AI (Anthropic): train models using AI feedback on their own outputs against a set of principles
  • Human feedback (RLHF): fine-tune models on human ratings of response quality

Alignment: The Core Problem

The alignment problem: how do you specify what you want an AI system to do, precisely enough that a system optimising for that specification actually does what you intended?

Classic examples:

  • "Make users happy" → system learns to addict users to endless scroll
  • "Get a high score in this game" → agent discovers an exploit that earns points without playing the game as intended
  • "Reduce hospital wait times" → system discharges sick patients early

Reward hacking: any learnable proxy metric can be gamed if the system is optimising it hard enough.

RLHF (Reinforcement Learning from Human Feedback): a leading approach to alignment. Train a reward model from human preference comparisons, then use RL to fine-tune the LLM to produce responses that the reward model rates highly. Used to train GPT-4, Claude, and Gemini.

The fundamental challenge: the reward model itself may have biases, blind spots, or specifications that diverge from true human values at the margin. Scalable oversight — how to supervise a system smarter than yourself — is an open research problem.

Privacy and Data

Training data privacy concerns:

  • Models can memorise training data, including personal information. LLMs can be prompted to reveal training data examples — including private information, copyrighted text, or PII.
  • Membership inference attacks: determine whether a specific example was in the training set.
  • Differential privacy: add calibrated noise to training or outputs to provide mathematical privacy guarantees (Laplace mechanism, Gaussian mechanism). At the cost of some model quality.

Copyright and consent:

  • Training on web-scraped data involves text, images, and code for which creators did not give permission
  • Multiple ongoing lawsuits (NYT vs OpenAI, Getty Images vs Stability AI, GitHub Copilot lawsuits)
  • Technical and legal resolution is evolving rapidly

AI Safety Frameworks

Red-teaming: systematically attempt to elicit harmful outputs from a model. Developed in security research, now standard practice before LLM deployment.

Responsible disclosure: when vulnerabilities are found in AI systems, how should they be reported? The same principles as software security but with less established norms.

Model cards: documentation accompanying ML models describing training data, evaluation metrics, known limitations, intended use cases, and out-of-scope uses. Introduced by Google researchers (Timnit Gebru et al., 2018).

Staged deployment: release models gradually (to researchers, then limited users, then generally) to identify failure modes before broad exposure.

Going Deeper

AI governance and regulation: the EU AI Act (2024) creates a risk-based framework: high-risk applications (medical, criminal justice, employment) require conformity assessments, transparency, and human oversight. Prohibited applications include: social scoring, real-time facial recognition in public spaces. Understanding the technical implications of compliance — what does it mean to document "training data characteristics" or provide "meaningful human oversight" for a production ML system — is a growing area of applied AI engineering.

AI consciousness and moral status: the question of whether AI systems can suffer or have interests is philosophically unresolved but increasingly practically relevant. As AI systems become more capable and exhibit more human-like behaviour, questions about their moral status will become urgent. Serious philosophers (David Chalmers, Nick Bostrom) and AI researchers (Geoffrey Hinton post-Google) engage with this seriously.

▸ Part A.1–3 — bias calculations

Setup: TP = correctly approved truly-creditworthy, FP = approved but not creditworthy, FN = denied but creditworthy, TN = correctly denied.

Group A: Approved=80, Denied=120, True creditworthy=100, True non-creditworthy=100. TP = min(80, 100) — we need more info to decompose. Assume model is miscalibrated: TP=70, FP=10, FN=30, TN=90.

  • Precision = 70/80 = 87.5%
  • Recall = 70/100 = 70%

Group B: Approved=40, Denied=60, True creditworthy=50, True non-creditworthy=50. Assume TP=35, FP=5, FN=15, TN=45.

  • Accuracy = (35+45)/100 = 80% (same!)

Equal recall means qualified applicants are approved at equal rates across groups.

▸ Part C.10–12 — mitigations

  1. Hallucination: Use RAG (Retrieval-Augmented Generation) — ground legal claims in retrieved authoritative sources. Add a citation requirement: the LLM must cite the document it retrieved. Add a confidence threshold: refuse to answer if retrieved evidence doesn't support the claim.

  2. Reward hacking: Use adversarial evaluation — generate borderline content and audit the model's decisions periodically. Add a human review quota (random sample of all "safe" decisions). Use a reward model trained on diverse stakeholder feedback, not just operator convenience.

Use adversarial debiasing: train an adversary to predict gender from the model's internal representations, penalise the model if the adversary succeeds.
